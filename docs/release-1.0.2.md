# Seen 1.0.2 — изменения и безопасное обновление

Дата: 29.09.2026. Статус: пакет для проверки на тестовом Mattermost; публичная production/HA приёмка не завершена.

## Изменение относительно 1.0.1

Добавлена подпись Сегодня/Today. Уточнены подписи существующих настроек RetentionDays (1–365, default 90) и EnablePublic в System Console; добавлены тесты reload/validation конфигурации. Подготовлен подробный live acceptance runbook с 35 сценариями. Ниже перечислены также унаследованные исправления 1.0.1.

## Что изменено

- Дата первого просмотра: сегодня `Сегодня, 11:24`; вчера `Вчера, 11:24`; раньше `27.09, 11:24`; другой год `27.09.2025, 11:24`. Используется часовой пояс пользователя, в tooltip и aria-label сохраняется полная дата. Открытый список обновляет относительные подписи каждые 30 секунд.
- Удаление сообщения заменяет KV-документ меткой `deleted` без списка viewers. После её успешной записи конкурентный CAS не может восстановить receipts. Метка сохраняется до максимального retention horizon + запас на часы; минимум сутки с удаления. Это минимальная связанная с post запись, а не полное физическое удаление всех следов post.
- Лимит на пользователя: 2 запроса/секунду, burst 120, на один plugin process; HTTP 429 и Retry-After. Карта лимитов ограничена 10000 пользователей и очищается. Состояние лимитов не является источником истины receipts и сбрасывается при перезапуске. Cluster-wide quota не заявляется.
- Для неизменного viewer list refresh загружает одну страницу вместо всех. При изменении списка полная перезагрузка ранее загруженных страниц сохраняется.
- После закрытия popover ненужные запросы профилей, ещё не начатые, пропускаются. Уже выполняемый общий запрос может завершиться; другой открытый потребитель не отменяется.
- Добавлены semantic lint и исправления React hooks, обновлён x/crypto; подготовлены public README/SECURITY/CHANGELOG/AI disclosure.

Plugin ID `ru.internal.mattermost.seen`, viewport dwell 800 ms / 50%, author-only permissions, deduplication и first stored timestamp сохранены. Прямого SQL и изменений системной схемы Mattermost нет.

## Предварительные проверки

Выполнять на тестовом контуре с синтетическими аккаунтами. Зафиксировать версию Mattermost, число app-нод, текущий пакет и настройки плагина, рабочий способ отключения и штатный backup БД. Для HA все app-ноды должны использовать общую writable DB; фактическая топология данным релизом не проверена.

Текущая логическая схема: браузер → Mattermost gateway → plugin process → shared Plugin KV. В HA процессов несколько, KV общий. Целевая схема та же; меняется формат удалённой KV-записи, а не топология сервиса.

## Порядок обновления

1. Сохранить архив установленной версии и настройки; подтвердить пригодность штатного backup.
2. Отключить плагин на всём кластере и проверить прекращение запросов/работы старых plugin processes. Новые просмотры в этот интервал не гарантируются, старые очереди браузеров ограничены по времени.
3. Загрузить новый `.tar.gz` под прежним plugin ID. Проверить версию 1.0.2 на каждой app-ноде.
4. Только после обновления всех нод включить плагин. Перезагрузить клиенты.
5. Выполнить сценарии из `acceptance-1.0.2.md` и сверить отображение даты с часовым поясом аккаунта.

Смешанный rolling upgrade со старой 1.0.0 не поддерживает новую гарантию: старый writer не понимает `deleted`. Отключение плагина влияет на индикаторы и сбор новых просмотров; остановка всего Mattermost не требуется этой процедурой, но поведение управления плагинами на конкретном кластере проверить отдельно.

## Проверка пакета

Где выполнять: на инженерной машине рядом с полученными архивами и файлом SHA256SUMS-1.0.2.txt. Проверяется целостность файлов, не доверие к их автору.

```sh
sha256sum -c SHA256SUMS-1.0.2.txt
```

Ожидаемый результат: `OK` для каждого перечисленного файла. При несовпадении не устанавливать пакет; повторно получить нужный архив и проверить источник.

## Откат

При сбое отключить плагин cluster-wide. Сохранить диагностику без cookies, token, текста сообщений и реальных viewer lists. Предпочтительный путь — совместимый исправленный пакет. Возвращение 1.0.0 с включёнными writes снимает гарантию tombstone; не выполнять такой откат как эквивалент безопасного обновления. KV вручную не удалять. Если необходим restore БД, учитывать влияние на весь Mattermost и выполнять только по штатному отдельно согласованному recovery runbook.

## Ограничения и диагностика

| Симптом | Вероятная причина | Проверка / действие |
|---|---|---|
| Показано «Вчера», хотя ожидалось сегодня | Часовой пояс профиля отличается от ожидаемого | Сверить Mattermost timezone и полную дату tooltip |
| HTTP 429, список временно обновляется медленно | Per-user или global in-flight limit | Проверить Retry-After; дождаться повтора; измерить нагрузку до изменения лимитов |
| HTTP 404 для viewers | Нет авторства/доступа, удалённое сообщение или tombstone | Проверить доступ тестовым аккаунтом; не обходить проверку прямым DB чтением |
| Warning `kv_tombstone` | Не удалось записать метку удаления | Проверить здоровье Mattermost KV/БД. Автоматическое гарантированное повторение deletion hook не реализовано |
| Просмотры не появились после reload офлайн-клиента | Недоставленная очередь была только в памяти | Это best-effort delivery; уже сохранённые сервером receipts от reload не теряются |

Dedicated erase по удалению пользователя/канала не реализован. Retention/physical KV cleanup/backup retention — разные механизмы. Уменьшение retention скрывает старые данные, но не переписывает физически все TTL сразу. Не обещать немедленную очистку при storage outage или удалении пользователя/канала.

Live gateway, реальные app1/app2, репликационная задержка и нагрузочный SLA остаются условиями production/HA приёмки. Исходный код public snapshot очищен отдельным allowlist; прежняя git history отсутствует и не проверена. GitHub private reporting необходимо включить владельцу будущего репозитория.
