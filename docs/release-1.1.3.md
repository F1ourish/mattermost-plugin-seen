# Seen 1.1.3 - пояснение о поддерживаемых клиентах

Добавлена сноска в preview и полный список просмотров:

> Учитываются только просмотры в Web/Desktop. Просмотры из мобильных приложений не учитываются из-за ограничений архитектуры Mattermost.

Сноска видна также при пустом списке, загрузке и ошибке, переведена на русский/английский и остаётся вне прокручиваемой части полного списка. Уточнены описание плагина, текст System Console и оба README.

Штатные iOS/Android-клиенты не запускают webapp-компонент плагина. Просмотр в мобильном приложении не создаёт receipt Seen. Отсутствие пользователя в списке не доказывает, что он не читал сообщение с телефона. Поддержка компонентов mobile описана в [официальной документации](https://docs.mattermost.com/developers/integrate/plugins/components/mobile).

Backend, dependency graph, plugin ID, схема KV, первое время регистрации, privacy/access checks и viewport-правила сохранены из 1.1.2. Серверные маркеры канала, fallback и код экспериментального 1.2.0 в этот patch не входят.

## Установка и проверка

Скачать install tar.gz и `SHA256SUMS-1.1.3.txt` из одного комплекта. В каталоге с этими файлами выполнить:

```bash
sha256sum -c SHA256SUMS-1.1.3.txt
```

Ожидаемый результат: `OK` для скачанных файлов и exit code 0. При неполном комплекте сверить конкретную строку SHA256 вместо полного check.

Сохранить предыдущий пакет и настройки. Загрузить `ru.internal.mattermost.seen-1.1.3.tar.gz` через System Console как обновление того же `ru.internal.mattermost.seen`. Проверить версию 1.1.3, активацию и значения `RetentionDays`/`EnablePublic`, затем полностью перезагрузить Web/Desktop.

Проверить сноску в preview и полном списке, на русском и английском, в светлой/тёмной теме и при нуле просмотров. Выполнить прежний smoke с двумя аккаунтами: новый viewport receipt из Web/Desktop появляется, повторный не меняет первое `seen_at`. Мобильный просмотр по-прежнему не создаёт отметку. Эти проверки на живом Mattermost выполняются отдельно от browser mock smoke.

Системная SQL-миграция и изменение правил сбора не требуются. Откат: вернуть пакет 1.1.2 того же ID и перезагрузить клиенты. Удалять plugin KV не нужно. На время отключения плагина его индикаторы и сбор не работают.

## Сборка и область проверок

Новая frontend-сборка проверяется lint/typecheck/unit/browser smoke. Контроль backend опирается на совпадение исходников и SHA256 обоих серверных бинарников с ранее проверенным 1.1.2. При локальной упаковке используются эти неизменённые бинарники, собранные Go 1.26.9; свежая Go-компиляция не заявляется. GitHub CI и актуальные dependency scans указываются по фактическому протоколу комплекта, а не по прошлой версии.

Этот patch сам по себе не подтверждает полную live/HA-приёмку.
