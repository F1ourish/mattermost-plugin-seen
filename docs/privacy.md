# Данные и приватность

База 1.0.3. Receipt показывает активность аккаунта; это персональные данные активности, даже без имени и текста сообщения.

| Данные | Место | Назначение / срок |
|---|---|---|
| Post ID в `v1:<post_id>`, user IDs, timestamps, expires_at | Mattermost Plugin KV | Retention от создания post; default 90, 1–365 дней |
| deleted tombstone без viewers | Тот же KV key | Защита от поздних writers; max(post creation + 366 дней, deletion + 1 день) |
| Очередь post IDs | Память клиента | До 500 pending/deferred, до 10 минут; reload теряет очередь |
| Профильные поля | Redux / ограниченный plugin cache | Отображение имени через штатный API; в receipts не сохраняются |
| Operation/category ошибок | Логи плагина | В reviewed logging нет списков viewers/текста; срок логов задаёт оператор |

Вызов native GetUser допустим; SQL к users не выполняется. Системная схема БД не меняется. Плагин не отправляет receipts в стороннюю аналитику. Native API может возвращать больше полей профиля, чем UI сохраняет: фильтрация frontend не уменьшает автоматически сетевой ответ Mattermost.

## Retention

Срок считается от создания сообщения, а не первого/последнего просмотра. Уменьшение настройки сразу ограничивает логическую доступность старых receipts, но не переписывает все физические TTL. Увеличение не продлевает автоматически ранее сохранённый expires_at и не возвращает удалённые записи. Отключение плагина не равно удалению его данных.

MessageHasBeenDeleted заменяет документ tombstone. Защита действует после успешного KV write, для новых writers. При ошибке записи автоматическое гарантированное стирание не доказано; отдельная очередь повторов очистки отсутствует. User/channel erasure workflow отсутствует. Физическая очистка KV, удаление плагина и сроки backup управляются Mattermost/оператором и требуют отдельной проверки; не обещать немедленное полное уничтожение данных.

## Граница доступа

Viewers доступны автору с текущим доступом к каналу; администратор БД/сервера и привилегированные server plugins находятся за этой границей. Уже показанные/скопированные данные невозможно отозвать из памяти пользователя или скриншота. Изменение членства не означает удаления ранее записанного receipt.

Перед организационным внедрением определить владельца данных, уведомление пользователей, retention/backups и процедуру запроса удаления. Это эксплуатационные решения; документ не является юридическим заключением. В public issues не прикладывать реальные IDs, viewer lists, HAR с cookies или рабочие переписки.
